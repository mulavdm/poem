# OKF Bundle Update Log

## 2026-07-16 (CI gates fixed — first-ever green pipeline expected)

- Discovered while releasing v0.3.0 that **POEM CI had never passed**: the v0.1.0 runs failed on the same two gates. (1) The gofmt gate failed because Windows runners materialize CRLF (machine `core.autocrlf true`, no `.gitattributes`) while committed blobs are LF-clean — added `.gitattributes` (`*.go`/`*.sh` `text eol=lf`). (2) The sidecar provenance gate bit-compared the embedded exe against a fresh runner build; MSVC image updates change codegen, so bit-identity across toolchains was never achievable. Re-anchored the gate to what it actually protects: a provenance manifest (`poem_cpp_sidecar.provenance`) fingerprints the **committed** `cpp_sidecar` sources (git blob hashes — deterministic on any checkout) at embed time; CI verifies the manifest matches current sources, proving the embedded exe was built from the tree's sources (verified: exe and sources last changed in the same commit, e32799e). The fresh Release build still gates compilation and still ships in the release zip. `RELEASING.md` documents the re-embed flow.

## 2026-07-16 (consolidation: one repo, one app API)

- Merged GopherWeb and Trellis into POEM per [Consolidation](/concepts/decisions/consolidation.md): GopherWeb components/middleware → `pkg/web` (branding stripped, `gw-`→`poem-`); Trellis `core` → `pkg/app` (the single public application API: `App[S]`/`Msg`/16 `Node` kinds), drivers → `pkg/app/desktop` and `pkg/app/web`; examples (counter/preferences/settings) → `examples/` running on all three targets from one Go definition. All migrated test suites pass in-module (driver, CSRF/session/FileStateStore, component families). Verified post-move: web counter serves with `poem-*` classes; Android counter APK rebuilt from the new import paths and a real tap advanced Count on the emulator. Supersedes `gopherweb-parity.md` (banner added) and Trellis's sister-project decision; the state-model finding (closures can't cross HTTP or serialize) is exactly why `App[S]` — not the component API — became the one public API. Follow-up: port the OKF bundle-validation Go test (lived in the dissolved repos).

## 2026-07-16 (Android presenter: counter milestone passed)

- Added `android_engine/`: a third POEM presenter — C++ / EGL / GLES2, hosted in a `NativeActivity` APK with **zero Java** (built by `build_apk.sh` with NDK clang + aapt2 + apksigner, no Gradle). It compiles `cpp_sidecar/src/protocol.cpp` directly and mirrors `RendererD3D11`'s command interpretation: SDF rounded rects, glyph quads from the Go-supplied atlas, scissor clip, offset, shadow/glow companion quads. Density scaling follows the Windows presenters' DPI split: the engine lays out in logical pixels (surface/density), the renderer scales geometry ×density; touch divides back. The host sends the initial `WindowSize` event after startup — the engine arms `NeedsRepaint` from it, exactly like the Windows sidecar (a black screen otherwise).
- Added `pkg/mobile` (android-only): in-process transport bridging `render.RunHosted` to the C++ host via exported `PoemHostRead`/`PoemHostWrite` (same framed POEM v2 byte protocol as the named pipes; one batched cgo crossing per direction per frame), plus stdio→logcat redirection (`poem-go` tag) so `fmt.Printf` breadcrumbs and Go panics are visible — stderr is otherwise a black hole inside an APK.
- **Milestone verified on the Android emulator**: the Trellis counter app — the identical Go `App[S]` driving Windows and web — rendered at density 420 (1080x2400 physical, 411x914 logical), and a real tap advanced state to `Count: 1` through touch → EventBatch → Go hit-test → `Update` → new frame. Known gaps, deliberate: no IME/soft keyboard, no audio, no accessibility bridge, no activity-lifecycle hardening, arm64 built but emulator-only verified.

## 2026-07-12 (tabs controlled selection)

- Fixed `components.Tabs` ignoring application-driven selection changes when **controlled**. `activeIndex` preferred the roving position stored in `TransientState` over `SelectedID` unconditionally, so once a user had clicked any tab, an application that later set `SelectedID` itself — without a click or keypress — was silently overridden by the stale roving position. That defeats the entire point of a controlled component: an app cannot programmatically move the selection (a "jump to this tab after saving" flow). `tabsInteraction` now also snapshots the application's `SelectedID` at the moment a roving position is stored, so `activeIndex` can tell "the application moved the selection" (snapshot differs from the current `SelectedID` → adopt it and resync the snapshot) from "the user roved" (snapshot matches → keep the roving position). The resync matters: without it, an application changing back to a previously snapshotted value would look unchanged and be shadowed again. Uncontrolled `Tabs` are unaffected. Added a regression test covering click-then-apply and application-driven change; the existing roving-survives-rebuild test still passes unchanged. Unblocked the sibling Trellis project's `TabsNode`, whose selection is application-owned.

## 2026-07-12 (accordion uncontrolled persistence)

- `components.Accordion` now persists **uncontrolled** expansion (`OnToggle == nil`) in the `ApplicationState` transient store, keyed by `CompID`, instead of only mutating the instance's `Expanded` map. Previously an uncontrolled accordion rebuilt from scratch each frame — which is how `BuildPagesFn` and the downstream Trellis runtime both drive rendering — silently dropped every toggle, because the mutated map was discarded on the next rebuild. It now hydrates `Expanded` from the transient store (seeded from the author's initial open set on first sight) at each state-aware entry point and writes back on toggle, exactly how `Tabs` selection and `Select` popups already survive rebuilds. Controlled accordions (`OnToggle` set) are unchanged — the application still owns their `Expanded` map. Added rebuild-persistence and default-open-seeding regression tests; all existing accordion tests still pass. This unblocked the sibling Trellis project's `AccordionNode` (backend-local expand/collapse chrome, no `App[S]` involvement).

## 2026-07-10
* **Migration**: Added `okf/concepts/decisions/` (POEM had none, despite `AGENTS.md` already listing "decisions" as a relationship the bundle should keep discoverable) and recorded `github.com/mulavdm/gopherweb-parity.md`: mirrored parallel APIs, not a shared UI representation, is the permanent architecture between POEM and GopherWeb, given the state-model and trust-boundary blockers found across this week's convergence work. Added a matching short section to `AGENTS.md` establishing the ongoing check-the-sibling-project practice.
* **Breaking change**: Renamed `components.TableColumn`'s `Title` field to `Label`, matching GopherWeb's `data.TableColumn.Label` and POEM's own established convention for item-list captions (`TabItem.Label`, `SelectOption.Label`, `BreadcrumbItem.Label`, `MenuItem.Label` all already say `Label`) — found while re-checking the "Partial match" components from the original audit for a Badge-style hidden win rather than taking the earlier "structural, leave it" call at face value. 13 sites, all in `virtual.go`, `cmd/gallery`, and test files; no OKF doc referenced the old name.
* **Breaking change**: Retyped `components.Badge`'s `Role TextRole` field to `Variant theme.Variant`, matching GopherWeb's `feedback.Badge.Variant` in both name and value set. This reverses an earlier decision (see the 2026-07-08 entry below) that called it "a type-level decision, not a naming one" — a closer read of `Badge.Draw` found it was already straining against `TextRole`'s limits, calling `textRoleColor` twice to fake a background `TextRole` has no real concept of, when what it actually wanted was the same background+foreground pair `buttonVisual`/`theme.Variant` already gives `Button`/`Toast`/`Tabs`/`Select`. Added `badgeVisual(theme.Theme, theme.Variant) (bg, fg color.RGBA)` in `style.go`, preserving Badge's exact prior visual formula (30%-mix tinted background, full-strength foreground) but keyed off `Variant`'s semantic colors; `VariantSecondary`/`VariantSubtle`/`VariantNeutral` all fall back to the muted default since the theme palette has no dedicated secondary hue (`buttonVisual`'s own `VariantSecondary` case has none either). `Label.Role`/`DynamicLabel.Role` were deliberately left on `TextRole` — they only ever need a flat text color, which is exactly what `TextRole` models; `Badge` was the one field mistyped from the start. Zero existing call sites set `Badge.Role` besides `cmd/gallery`, which is updated in the same commit; Badge had no prior test coverage, now covered by `badge_test.go`.
* **Feature**: Fixed a bug where `automationPressKey("Escape")` silently no-op'd against an open `Modal` — unlike real keyboard input, the automation `/press-key` path dispatches Escape straight to `Component.OnKey` rather than through `run.go`'s global `DismissTopOverlay()` handler, and `Modal.OnKey` had no Escape case. `Modal.OnKey` now handles Escape itself (calling `OnDismiss` when set), mirroring the self-contained pattern already used by `Menu`/`Toast`/`Select`/`Autocomplete`/`DatePicker`. Added `ApplicationState.OpenModal(id, component, onDismiss)` as a named convenience (alongside the existing `OpenAnchoredOverlay`/`OpenFocusedOverlay` family) that defaults `dismissOnEscape=true` so callers no longer need to remember that `OpenOverlay` parameter; `cmd/gallery` now uses it. `Dialog` gained an `OnDismiss` field so `NewAlertDialog`'s existing `onDismiss` callback also reaches its composed `Modal`, not just the OK button. Purely additive — no existing exported signatures changed. Motivated by borrowing GopherWeb's `widget.Modal` Escape-to-close behavior as part of the cross-project parity roadmap; POEM's focus trap and initial-focus/focus-restore behavior were found to already exist generically in `ApplicationState.CycleFocus`/`openOverlay`, so no changes were needed there.
* **Feature**: Added an optional help/error text row to `LabeledBox` (`Help`/`Error string` fields), borrowing GopherWeb's `form.Field` help/error slot. Deliberately simplified to a single reserved row (`Error` wins over `Help` when both are set) rather than GopherWeb's simultaneous two-row layout, to stay inside `LabeledBox`'s existing fixed-arithmetic sizing model instead of turning a quick win into a layout rewrite. The description text is wired into the child's `Relations.DescribedBy` (POEM's `semantics.Relationships.DescribedBy` field existed but had no producer anywhere in the component library until now), with `RoleAlert` when `Error` is set to match GopherWeb's `role="alert"` on its error span.
* **Breaking change**: Renamed `components.Button.Label` → `Button.Text` (aligning with POEM's own `Badge.Text`/`Paragraph.Text`/`Label.Text` convention and GopherWeb's `action.Button.Text`), and `components.TextInput.Text` → `Value` / `components.TextArea.Text` → `Value` (aligning with GopherWeb's `form.Input.Value`/`form.Textarea.Value` and POEM's own `Select.Value`/`Slider.Value`/`DatePicker.Value` convention). Part of the same GopherWeb naming-convergence effort as the `Variant` rename below. `Select`, `Tabs`, and `Breadcrumbs` needed no changes — their overlapping fields (`Options`/`Value`/`Label`/`Items`/`Disabled`) already matched GopherWeb by name. `Badge`'s `Role TextRole` vs. GopherWeb's `Variant components.Variant` was deliberately left unreconciled — the two enums don't share a value set, so unifying them is a type-level decision, not a naming one. Downstream consumers referencing the old field names by name will fail to compile; there is no compatibility alias.
* **Breaking change**: Renamed `theme.Variant` constants `VariantDestructive` → `VariantDanger` and `VariantDefault` → `VariantNeutral` (plus their `pkg/render` public re-exports) to converge naming with the sibling GopherWeb project's `components.Variant` enum, which already used `Danger` and `Neutral`. `VariantDefault`/`VariantNeutral` remains the zero value. POEM's `VariantSubtle` (a borderless/ghost button treatment) has no GopherWeb counterpart and was deliberately left unrenamed — GopherWeb's Button CSS has no matching borderless variant, so folding it into `Neutral` would have misrepresented the actual styling. Downstream consumers importing `VariantDestructive` or `VariantDefault` by name will fail to compile; there is no compatibility alias.
